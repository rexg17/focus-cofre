# Design decisions

🌐 **English** · [Português](../pt-BR/DECISOES.md) · [Español](../es/DECISIONES.md) · [← README](../../README.md)

Each decision records the context, the choice and the price paid for it.

## 1. Local-first with SQLite
**Context:** financial data is sensitive and the app is used by one person.
**Choice:** everything in a local SQLite file, no accounts and no remote server.
**Price:** no sync between devices. Mitigation: daily backup, an extra backup folder and text export.

## 2. Write the whole state in one transaction
**Choice:** `PUT /api/state` validates everything and replaces the tables inside a `BEGIN IMMEDIATE`; any error rolls back.
**Why:** it is simple to reason about and cannot leave the database half-written.
**Price:** cost proportional to the size of the state. Measured: with 20,000 entries the screen renders in about 50 ms.

## 3. Money in cents and FX per transaction
**Choice:** `INTEGER` cents in the database; each foreign-currency item stores that day's rate.
**Why:** it avoids rounding errors and stops today's rate change from rewriting the revenue of old months (a real
flaw found in the audit).

## 4. Plain JavaScript, no framework, no build
**Choice:** classic modules loaded in order, global state and rendering with template strings.
**Why:** zero toolchain, easy to read and to package.
**Price:** no types and no components. The single publishable file is generated by `tools/bundle.py`.
**If it grows:** move to ES modules and TypeScript, keeping the financial engine as pure functions.

## 5. Financial engine in the browser; the server only persists
**Why:** the screen recomputes on every click and the AI tools run next to the data. The server validates and stores.

## 6. The API key stays on the local server only
**Choice:** the browser calls `/api/llm`; the server builds the request with the official SDK.
**Why:** the key never appears in JavaScript, state, backup or screen (`/api/settings` only says whether one exists).

## 7. AI with tools (tool use), not data in the prompt
**Choice:** the AI asks the app for calculations (`visao_geral`, `simular_dividas`, `previsao_caixa`…) and receives
aggregates only.
**Why:** (a) it does not invent numbers, (b) privacy is decided by which tools exist, (c) the local engine remains the
source of truth, with tests.

## 8. Not training a model of our own
Training an LLM would make no sense for this problem. The gain comes from **correct data, tested rules and a good model
that uses tools**. The coach works with local rules even without the AI.

## 9. Default model and fallback
Default `claude-opus-5-5`, changeable in settings. The app turns on the API's fallback feature in case an answer is
declined for safety reasons. The request sends no sampling parameters and does not disable reasoning, and reasoning
blocks come back untouched on every turn of the tool loop (covered by a test).

## 10. A window through Edge/Chrome in the portable package
**Context:** `pywebview` on Windows depends on `pythonnet`, .NET and WebView2.
**Choice:** the portable package opens the local address in Edge/Chrome in app mode (`--app=`), which Windows 10/11
already ships. `pywebview` is still used if installed (PyInstaller build).
**Price:** the window lifecycle must be inferred, hence the liveness signal (`ping`/`bye`).

## 11. A Windows package assembled from Linux
**Choice:** a Go launcher (trivial cross-compilation) + the official Python from NuGet + native libraries downloaded
with `pip download --platform win_amd64`. Nothing is installed on Windows and the result is a folder you can delete.
**Price:** without a paid digital signature SmartScreen warns; and the package could not be run on real Windows here.

## 12. Transparent heuristics
The thresholds of the rules (60/40, 1.5× the average, etc.) are fixed and visible. Each coach action carries a
"how the app got there" table so you can disagree with arguments.

## 13. A fake API server in tests
A fake HTTP server (`tests/fake_anthropic.py`) imitates the API and records what it received. The tests therefore check
headers, body, `fallbacks`, the absence of forbidden parameters and the untouched return of reasoning blocks, with no
key and no cost.
